# ScreenFlow 1.2 — Windows画面連続撮影・一括トリミング・PDF

撮影 → 範囲指定 → 一括トリミング → PDF作成を1つのGUIで操作するローカルアプリです。

## 1.2の変更点

- PDF画質を「低画質・中画質・高画質」から選べます。初期選択は中画質です。
- デフォルトのPDF名を `capture_20261112_1330.pdf` の形式にしました。日時はWindowsのローカル時刻です。同名があれば `_2`、`_3` と連番を付けます。
- 自動のファイル名はPDFタブ表示時・作成直前に更新し、作成完了後は次の空き名を表示します。自分で変更した名前は維持します。
- 作成完了時にPDFの容量を表示します。

## 1.1で追加した機能

- 撮影タブでページ送りを「右矢印（→）」「左矢印（←）」から選べます。
- トリミングタブで範囲指定用の画像を一覧・前後ボタンから選べます。拡大確認もその画像を使用します。
- 同じ画像サイズでページを切り替えた場合、指定済みの範囲を保持します。実際の画像寸法が違う場合は範囲を解除します。
- 一括トリミングは表紙を含む全画像に元の順序で適用します。実際のファイル寸法が異なる場合の検出・停止も継続します。

更新するときは、新しいZIPを別フォルダへすべて展開して `START.cmd` を起動してください。既存の撮影画像は「画像フォルダを開く…」から再利用できます。

## 最初に起動する

1. ZIPを**すべて展開**します。ZIP内から直接起動しないでください。
2. 展開した `screenflow` フォルダ内の **`START.cmd` をダブルクリック**します。
3. 初回だけuvが必要なライブラリをインストールします。完了するとGUIが開きます。

Windows 11 x64、Python 3.12、uvが前提です。初回のライブラリ取得にはインターネット接続が必要です。以後も同じ `START.cmd` から起動でき、コマンド入力は不要です。通常の起動では依存ライブラリの再取得を行いません。画像処理と撮影は端末内で完結し、画像を送信しません。

起動できない場合は、インストール時のウィンドウに表示されたエラーを確認してください。GUI起動時のPython例外はメッセージと `%LOCALAPPDATA%\ScreenFlow\startup_error.log` に表示・保存されます。設定や保存した画像がログへ送信されることはありません。

## まず5枚で試す

1. 撮影対象を**メインディスプレイ**に置きます。
2. 「1 撮影」で枚数を **5**、ページ送り待機を **1.5秒**、準備時間を **10秒**にします。
3. 「ページ送りの方向」で対象アプリに合う「右矢印（→）」または「左矢印（←）」を選び、保存先を選び「撮影開始」を押します。アプリは最小化されます。
4. 10秒以内に撮影対象のウィンドウを最前面にします。
5. 1枚目を撮影 → 選択した矢印キー → 1.5秒待機を繰り返します。5枚目の後はキーを送りません。
6. 終了後にアプリが戻ります。「撮影画像をトリミングへ →」を押します。
7. 「範囲指定に使う画像」の一覧、または「前の画像」「次の画像」で本文ページを選び、画像上をドラッグして残す範囲を指定します。表紙を基準にする必要はありません。
8. 必要なら「100%」「＋」「−」「選択範囲を拡大確認」を使います。拡大時はスクロールバーで移動できます。再ドラッグで選び直し、「選択解除」で消去します。
9. 「全画像を一括トリミング」を押します。
10. 「トリミング画像をPDFへ →」を押し、画質とPDF保存先を指定して「PDFを作成」を押します。ファイル名には日時が自動で入り、必要なら変更できます。
11. 「完成したPDFを開く」で確認します。

撮影を省略し、トリミングタブの「画像フォルダを開く…」から既存の画像を読み込めます。トリミングを省略するときはPDFタブで直接入力画像フォルダを選びます。「直前にトリミングした画像を使用する」のチェックで入力元を切り替えられます。

## 停止方法

- **撮影中：F8を押す**。対象アプリへ送られる矢印キーとは別に監視しています。
- **撮影中：マウスをメインディスプレイの隅へ移動する**。PyAutoGUIのフェイルセーフを使います。
- アプリの「処理を停止」でも中止できます。撮影中にアプリを最前面に戻すと、撮影対象の変更として停止します。
- 最前面ウィンドウが途中で変わった場合も停止します。撮影中はほかのウィンドウを操作しないでください。
- 保存や画像の変換を強制終了せず、現在の1枚またはファイル書き込みの区切りで止めます。停止要求直前に始まった操作が1回完了する場合があります。
- 処理中に閉じると停止を要求します。停止後にもう一度閉じてください。

## 保存と並び順

- 撮影元画像：指定先の `capture_日時_識別子` 内に `page_000001.png` などで保存します。
- 切り抜き画像：指定先の `cropped_日時_識別子` 内に保存します。元画像は上書き・削除しません。
- 入力は選択したフォルダ直下のPNG/JPG/JPEGです。サブフォルダは再帰的に読みません。
- ファイルは自然順です。例：`page_1.png → page_2.png → page_10.png`。撮影・トリミング出力も同じ順序になります。
- 座標はEXIFの向きを反映した元画像のピクセル単位です。右端・下端は含みません。
- 一括トリミング前に全画像を読み、範囲指定に使った画像と寸法が違う画像や破損画像があれば、ファイル名を表示して出力前に中止します。
- 中止・失敗時も、それまでに完成した撮影画像や切り抜き画像は残ります。途中の切り抜き結果は出力先の `cropped_…` を確認してください。
- PDFは一時ファイルを作ってから完成ファイルを公開します。自動名は既存ファイルを避けます。手動指定した名前が既存PDFと重なる場合は上書きを確認します。失敗・中止したPDFで既存PDFを置き換えません。

## PDFとメモリ

img2pdfを使用し、1画像を1ページにします。縦横比を保持し、ページの物理寸法は96dpi相当に設定します。

| 選択 | 最大の長辺 | PDF内の画像 | 用途 |
| --- | --- | --- | --- |
| 低画質 | 1600px | JPEG品質65 | ファイル容量を優先 |
| 中画質（初期設定） | 2560px | JPEG品質85 | 閲覧用の標準設定 |
| 高画質 | 元の画素数 | 元画質を保持 | 細部を優先。容量は従来と同じく大きくなる |

低・中画質は元画像が上限より大きい場合だけ縮小します。小さな画像は拡大しません。カラーは維持し、透過部分は白背景に合成します。縮小・JPEG変換はPDF内に格納するデータに対して行い、撮影したPNGやトリミング済みのPNGは書き換えません。EXIFの回転・反転は全画質で反映します。高画質では通常のJPEGを再圧縮せず埋め込みます。

容量削減の程度は画像の内容によります。文字の細かいページは、まず中画質で数ページ作成して確認してください。

全画像を展開したPillow画像として同時保持しません。検査と変換は1枚ずつ行います。ただしPDFライブラリは圧縮済み画像データを文書内に保持するため、メモリ使用量は出力PDFの総量に応じて増えます。定量的な上限やWindowsの大規模撮影性能は未計測です。

## Windows実機で確認する項目（未実施）

この配布版はLinux環境で自動テスト済みです。**Windowsの実際の画面撮影・F8検出・キー送信・起動バッチ・EXEビルドは未検証**です。最初は上記の5枚で確認してください。

- GUIが起動する。
- 準備時間内に撮影対象へ切り替えられ、アプリ自身が写らない。
- 選んだ右または左矢印でページが進み、最後は送られない。
- 保存画像のサイズ・内容・順番が正しい。
- F8と画面の隅による停止が使える。
- 対象ウィンドウを切り替えると停止する。
- ドラッグ範囲と実際の切り抜き位置が一致する（Windows拡大率100%/125%/150%など）。
- PDFの順序・画質・縦横比が正しく、ローカルのPDFビューアーで開ける。

対象アプリが選択した矢印キーを受け付けることが前提です。撮影対象を管理者権限で動かすと、通常権限のアプリからキー送信できない場合があります。複数モニターの一括撮影、モニター指定、画面保護の解除には対応していません。

## 開発者向け

最小構成です。データベース、サーバー、クラウド同期は使いません。

| ファイル | 役割 |
| --- | --- |
| `app.py` | 3タブGUI、ワーカースレッド、範囲選択 |
| `core.py` | 自然順、画像検査、切り抜き、PDF、撮影手順 |
| `capture_windows.py` | PyAutoGUIとWindowsの最前面/F8監視 |
| `launch.pyw` | コンソールなしの起動・起動エラー表示 |
| `START.cmd` | 初回準備と通常起動 |
| `BUILD_EXE.cmd` | 任意のWindows EXEビルド |
| `tests/` | 画像処理・PDF・撮影手順・GUIのテスト |
| `TEST_RESULTS.md` | 実施した検証と未検証項目 |

PySide6のQtWidgetsを含む `PySide6-Essentials` を使用し、不要なWebEngine等は含めていません。依存関係は `pyproject.toml` と `uv.lock` に記録しています。

開発起動：

```powershell
uv sync --locked
uv run --locked python app.py
```

テスト：

```powershell
uv run --locked pytest -q
```

GUIテストはオフスクリーン描画を使い、撮影手順テストは偽の画面操作を使います。実際のデスクトップにキーを送信しません。

### 任意のEXE化

Windows上で `BUILD_EXE.cmd` をダブルクリックします。開発者向け依存関係を取得し、PyInstallerで `dist\ScreenFlow\ScreenFlow.exe` を作ります。配布するときは**ScreenFlowフォルダ全体**が必要です。単独exeではありません。

ビルドコマンド：

```powershell
uv run --locked --no-dev --group build pyinstaller --noconfirm --clean --windowed --onedir --name ScreenFlow --collect-all img2pdf --collect-all pyautogui launch.pyw
```

LinuxからWindows用exeを作る手順は含めていません。ビルド後も同じ5枚テストが必要です。第三者への配布時は使用ライブラリのライセンス・同梱通知も確認してください。
