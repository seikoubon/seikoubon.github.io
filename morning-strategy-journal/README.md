# 日本株AI 朝の戦略日誌

日本時間の取引営業日8:30に、AIが朝のニュース、米国市場、日経225先物を読み、既存研究を踏まえて当日の仮想売買を決める。仮想資金500万円は既存のAI TRADER 500から独立した現金口座。目的はコスト控除後の資産を増やすこと。採用、併用、見送りを選べる。

## 1回の処理

1. JPXの現物市場の営業日を確認する。開始前の休場日は投稿しない。日誌の対象日は予定時刻の日本日付。8:30より早い起動なら定刻を待ち、8:30までに取得可能だった情報だけで判断する。判断時刻は実時刻で記録する。
2. `data/ledger.json` を読み、最後の確定日から前営業日までの確認可能な取引を日付順に精算する。事前記録の注文を同日の日足に照合し、その日の終値で保有を評価する。公表価格と日付・出典を確認し、約定・不成立・保留を明記する。未確定の注文、残高、評価額を確定する前に差し戻しが必要な場合は保留する。既存AI TRADER 500の台帳は比較値の取得だけに使う。
3. 米国市場は最新の確定セッションの日付と動きを記載し、休場時は最後の取引日を明示する。日経225先物は取引所・限月・時刻・比較基準を確認する。朝の国内ニュースは、企業開示や取引所等の一次資料を優先して時刻とURLを残す。数字が確認できない場合は欠測とし、判断に必要なら見送る。見出しと価格の変化からの推論は事実と区別して書く。
4. カタログの中から戦略を選ぶか、見送る。候補銘柄と必要データを寄り前に確認し、相場材料が戦略の選択や除外にどう結びついたかを書く。保有分の決済はエントリー時に確定したルールに従う。9:00までに公開用台帳への保存が間に合わなければ当日の新規注文を発行せず、遅延による見送りを記録する。前回の判断本文を結果に合わせて書き換えない。
5. 既存日を確認してからGitHubの正本を最新blob SHAで更新し、再取得して内容を検証する。競合時は再取得し、決定済みの注文を二重追加しない。同日の既存判断のある再実行でも、保留中の結果を追記できる。二重の精算と残高更新を防ぐ。書き込み先はこの実験の `data/ledger.json` のみ。

## 戦略の選択対象

寄り引け・スイングの過去検証で蓄積した2,000案以上の全戦略を朝の選択対象にする。台帳の各案には元の戦略ID、対象、発注条件、決済条件、必要な朝のデータ、既存の検証結果への参照を持たせる。元台帳の件数と照合できる版を使う。各営業日はニュース、米国市場、日経225先物の状況を踏まえ、条件に合う戦略を絞り込む。日誌には台帳の版、収録件数、当日適用できる候補数と、選んだ理由を記録する。

全戦略台帳の接続状況は準備中。朝の実行から台帳を読み取れない場合は、ニュース、確認済みの取引結果とともに「全戦略台帳未接続」と記録し、新規の仮想注文は見送る。元研究の概要と代表例は [寄り引け全案のスイング検証](../japan-swing-research/swing-validation-2026-11-20/) に掲載。

## 口座と成績

現物・買い建て、売買単位を確認。不足資金を使わない。1銘柄の新規買いは前回確定総資産の20%まで、同時保有は最大10銘柄、重複保有は追加しない。新規買いの拘束額は指値×株数、寄成は確認した当日の値幅上限×株数。売り代金の同日再投資はせず、翌営業日から使う。往復0 bpの仮想約定として記録し、比較時に費用の前提を明記する。実口座への接続や注文は扱わない。

寄成は東証の前場始値。買い指値は始値が指値以下なら始値、次に安値が指値以下なら指値。売り指値は始値が指値以上なら始値、次に高値が指値以上なら指値。当日限り、部分約定なし。有効な取引価格や約定可否が確認できないものは保留。引けの決済は事前の決済ルールで確定したものだけを当日終値で照合し、取引停止や約定不能時は次の執行可能な引けに持ち越す。分割・配当等の企業行動は取引・権利情報を確認し、会計処理が不明な期間は比較確定を保留する。

既存運用は [AI TRADER 500](../ai-trader-500/) の確定引け評価を使う。2026年11月20日引けの4,803,500円（現金3,978,250円と保有時価825,250円）を基準にする。既存運用の500万円換算額は、比較する日の既存総資産÷4,803,500×5,000,000。以後の保有分の値動きは含める。両口座が同じ日付の引け評価を確定できた日のみ、横並びで掲載する。新口座の初回判断時は前回取引なしと表示する。

## 台帳形式

- `journal[]` は `{date, decision_at_jst, strategy, action, market, reason, orders_text, review, sources}`。文字列を使い、`sources` は `[{label,url}]`。初回・休み明けを含め、`review` にどの営業日の結果かを記載。ニュースのURLと判断の理由を含める。
- `orders[]` は注文ID・営業日・戦略ID・実際の判断時刻・銘柄コードと銘柄名・売買方向・株数・注文種別と価格・拘束額・予定決済日・状態・約定価格・出典を保持。先に持ち越した取引が未確定で残高が不確かな日は、新規買いを見送る。
- `holdings[]` は銘柄、株数、取得単価、建て日、戦略、予定決済日。現金は整数円で持ち、端数丸めは残高計算上で一貫させる。
- `closes[]` は `{date, cash_jpy, holdings_value_jpy, total_jpy, existing_total_jpy, status, sources}`。確認済みなら `status: "confirmed_close"`、欠測は `"pending_unverified"`。比較元の同日確定値がなければ `existing_total_jpy: null`。欠測に0円を入れない。
