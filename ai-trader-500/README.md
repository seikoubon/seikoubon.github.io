# AI TRADER 500 — 公開仮想株式運用実験

## 概要
実資金ゼロ・初期仮想資金 **5,000,000円**。2026-11-13（金）から平日運用を試行する（初回は8:40 JSTに臨時起動し、以後の定期実行は平日8:30）。AIが日本株・国内上場ETFの銘柄選択、注文方針、数量を独立して決め、AIが投資日誌を書く。ユーザーは売買判断に介入しない。運用期限は設けない。成績は期間別に評価する。

- 画面：`https://seikoubon.github.io/ai-trader-500/`（GitHub Pages の公開設定と配信は要確認）
- **唯一の正本**：`data/ledger.json`
- 関連しない既存ファイルを編集・移動・削除しない
- 本番の証券口座、発注、決済、資金移動を一切しない
- このフォルダの公開内容は仮想運用記録のみ。実際の取引推奨ではない

## 運用サイクル（日本時間）
1. **8:30 朝判断** — 現時点で公開・取得できる市場情報に限って調査し、前場寄り（9:00）での買い・売り・見送りを判断。判断時刻と参照元URLを保存する。時刻に遅れて寄りが始まったら、寄り注文は作らず見送りを記録する。
2. **16:00 引け後照合** — 事前の注文判断と実際の取引所価格を照合。**市場始値が確かな銘柄だけ**仮想約定として反映し、保有銘柄の時価評価を行う。データ不足なら`pending_unverified`とし、翌営業日に検証を持ち越す。情報が得られないのに売買成立・資産評価を作らない。
3. まずは朝・夕の2回で開始。前引け、後場寄り、大引けの独立売買判断は、安定稼働を確認してから拡張する。

## リスク・約定管理
- 現物・買い建てのみ。レバレッジ、空売り、米国株、単元未満株は初期段階では利用しない。
- 東証の通常売買単位とETF各銘柄の規定単位を守る。
- **成行買いの資金拘束額**は当日適用される値幅制限のストップ高価格×株数（および該当する諸経費）。値幅制限は信頼できる根拠で検証する。確認できない場合は「余力判定不可」として発注を見送る。適当な110%固定や未来の価格を使わない。
- 発注時に利用可能額（現金−他の未約定買い注文拘束額）以上を使わない。
- 仮想約定は事前に決めた注文方法と、事後に確認した対応セッションの価格でのみ判定する。寄成は東証の前場寄り値を原則とする。ただし寄り付かない／特別気配／ストップ高買いなど成立しない可能性がある場合は未確定とする。
- 取引時刻の遡及、事後的な有利な約定価格の選択は禁止。
- 約定した買いのみ現金から差し引く。売りは保有数量以上を認めず、約定確認後に現金に加える。売却代金の再利用・受渡しなどの規則は、シミュレーション用に別途明記する。最初は売却代金の同日再利用を行わない。
- 現金、株数、平均取得単価、取得額、時価、損益を整合させる。
- 価格、価格基準日、出典URL、参照時刻を記録する。株価が未取得のときは古い評価額を「最新」と称さない。
- 平日でも祝日・休場なら売買なし。外部確認できない場合は保守的に見送る。

## 運用担当AIへの指示
- 人間の保有銘柄や好みに迎合せず、独自に最適だと考える戦略を実行する。
- 新規銘柄・保有銘柄・現金保有を毎回同等に検討する。無理に売買せず`no_trade`も正式判断とする。
- 判断は具体的な銘柄コード、売買、株数、注文種類、対象セッション、判断理由（最大3点）、撤退・見直し条件まで確定する。
- 人間に「半分どうしますか」と尋ねない。決定不能なら具体的理由を記録して`no_trade`とする。
- 売買判断と客観的検証は別。損益結果を見て当初の理由を後から変更しない。
- 同じ`date+slot`に2重の注文・記事・評価を追加しない。

## data/ledger.json （単一正本）
- `capital_jpy`: 初期資金（固定）
- `cash_jpy`: 未拘束を含む現金総額
- `holdings`: `[{code,name,quantity,average_cost_jpy,market_price_jpy,market_value_jpy,price_date,source_url}]`
- `orders`: `[{id,decision_at_jst,code,name,side,quantity,order_type,session,limit_price_jpy,buying_power_hold_jpy,status,decision_sources,reason,fill_price_jpy,fill_date,fill_source_url}]`
  - 状態：`planned`, `filled`, `unfilled`, `pending_unverified`, `cancelled`, `skipped_late`
- `equity_history`: 営業日単位で`[{date,phase,cash_jpy,holdings_value_jpy,total_jpy,topix_equivalent_jpy,nikkei_equivalent_jpy,price_status,sources}]`
  - 確定終値なしの保有銘柄があれば`price_status=stale_or_missing`で記録し、未確認の総資産を確定値として掲載しない。
- `journal`: `[{id,time_jst,type,title,body,order_ids}]`
- `last_decision`, `last_settlement`, `run_logs`, `data_quality`

**更新前に現在のSHAを取り、1コミットでledger.jsonを置換すること。** 更新失敗時に新しい状態を仮定しない。更新後はGitHubの同じファイルを再取得し、保存内容とコミットを照合してから成功報告する。

## ベンチマーク
TOPIX・日経平均の各開始日終値を100%として初期資金500万円換算で別系列に記録する。採用価格・日付・出典を必ず持ち、未取得なら null とする。実験開始日からの変化率を比較する。AIの現金込みの実績とインデックスのリスク差を併記する。

## 公開ブログ
AIの一人称で「何を何株、なぜ、いつ買う・売る／見送る」を短く書く。判断時点の記事と、事後の約定・成績報告を分ける。判断はappend-onlyの記録として残す。GitHubコミット履歴が監査証跡となる。

## 再スタート
失敗時は新しい`portfolio_id`と初期5,000,000円から新しい実験として開始可能。ただし旧成績を上書きせずアーカイブして比較可能にする。エラー対応のために過剰な管理機構を増やさず、まず実際の売買判断と確定約定の1サイクルを優先する。
